`traffic/hot-partition` demonstrates two distinct ways a key distribution creates a hot partition:

```yaml
topics:
  - name: user-events
    partitions: 12
    consumers_per_group: 3
    producer_rate: 1000
    message_schema:
      key_distribution: zipfian
      key_cardinality: 100

  - name: transactions
    partitions: 12
    consumers_per_group: 3
    producer_rate: 500
    message_schema:
      key_distribution: single_key
      key_cardinality: 1
```

- **`user-events`** uses `zipfian`: a small number of keys receive disproportionately more
  traffic, the way a real "power user" or "popular product" key distribution behaves.
- **`transactions`** uses `single_key`: every message shares one literal key, so every message
  lands on the same partition. It's the most extreme case, useful for confirming your consumers
  and dashboards actually surface a fully saturated single partition rather than averaging it away
  across the topic.
